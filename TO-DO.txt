WORKFLOW A — ADD A NEW PDF-BASED PRACTICE TEST
==============================================================

Pattern established by: baseline, final, 4th practice tests.

STEP 1 — Create a new folder with the PDFs
  practice-test-<name>/
    *.pdf

STEP 2 — Open Claude in the project
  cd /home/mrahman/claude/projects/nh-cpt-practice
  claude

STEP 3 — Paste this prompt (edit [bracketed] parts)

  i added a new folder "practice-test-[name]/" with PDFs.
  Please build a new practice-test page from these PDFs, same
  pattern as baseline/final/4th. Target ~150 questions, 25 per
  test, with Past Tests history and download, linked from
  index.html with a back-to-index button. Push to GitHub when done.

WHAT CLAUDE WILL DO AUTOMATICALLY
  1. Extract text from each PDF (pypdf in a venv at /tmp/pdf-extract/)
  2. Identify unique facts across the 5 NHA CPT domains:
       SC = Safety & Compliance
       PP = Patient Prep
       RC = Routine Collections
       SP = Special Collections
       PR = Processing
  3. Write a question bank (target 150 MCQs, 4 choices each).
     Mix should roughly reflect the PDF content coverage.
  4. Create <name>_practice_test.html cloned from baseline:
       - 25 random questions per run
       - Submit & Grade with per-domain breakdown and pass/fail at 75%
       - Show Answer Key view
       - Download Test (.txt) with questions, your answers, correct answers
       - Past Tests history saved to localStorage (independent per page,
         keyed as nhaCpt<Name>History / nhaCpt<Name>Current)
       - "← Back to Index" link in header
       - A UNIQUE theme color so pages are visually distinct
         (used so far: blue, green, purple, orange — pick a new one)
  5. Update index.html:
       - Add a new card under "Full-Length Random Practice"
       - Add a new stat tile with the bank size
  6. Commit (as sujan00-git) and push to origin/main
  7. GitHub Pages redeploys in about 1 minute

VALIDATION CLAUDE SHOULD RUN BEFORE PUSHING
  node -e "..." against the bank:
    - total count
    - per-domain mix
    - no bad entries (4 choices, answer 0-3, domain set)
    - no duplicate question text
  Smoke-test the <script> with a jsdom stub.

GIT IDENTITY (prior commits used this; no global config set)
  git -c user.name='sujan00-git' \
      -c user.email='sujan00-git@users.noreply.github.com' \
      commit -m "..."

NAMING CONVENTIONS
  Folder:  practice-test-<name>/
  Page:    <name>_practice_test.html
  Keys:    nhaCpt<Name>History / nhaCpt<Name>Current
  Theme:   unique CSS primary color + matching card gradient

NOTES ABOUT PDF CONTENT
  - If the folder has <ADS Zone.Identifier> sidecar files (from Windows),
    do NOT commit them. Stage only the .pdf files explicitly.
  - If the content overlaps heavily with the baseline PDFs, Claude will
    still write a complete bank for that page so it stands alone. Each

==============================================================
TEST HISTORY — SAVE / RESTORE VIA GIT
==============================================================

Each PDF-based test page saves every test you take to the browser's
localStorage automatically ("Past Tests" button). To make that history
survive clearing the browser or moving to another device, use the
tests-history/ folder in the repo.

Workflow:
  1. Take tests in the browser as usual.
  2. Click "Export All" on the test page — downloads <page>-history.json
  3. Drop the file into tests-history/ with the matching name:
       baseline-history.json  (for baseline_practice_test.html)
       final-history.json     (for final_practice_test.html)
       fourth-history.json    (for fourth_practice_test.html)
  4. git add tests-history/ && git commit && git push
  5. On any device, open the live site. The page auto-fetches the
     committed JSON and merges it into Past Tests.

Merge rules on each page load:
  - Same test id → the record with the newer timestamp wins
  - A graded record wins over an ungraded one with the same id
  - Everything else is appended

Manual Import: use the "Import" button to load a .json picked from disk.

See tests-history/README.md for the file format.

Adding a NEW PDF-based test page: also create
  tests-history/<name>-history.json  (initial contents: [])
and define HISTORY_FILE + EXPORT_FILENAME in the page's script.
